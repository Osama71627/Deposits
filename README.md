# Deposits | منصة إدارة التخزين والخدمات اللوجستية

**منصة ويب عربية تجمع إدارة طلبات التخزين والمستودعات والمندوبين والعمليات الإدارية في مشروع Django واحد.**

Deposits is an Arabic-first storage and courier management platform built with Django and Django REST Framework. It combines customer requests, warehouse inventory, courier operations, and administrative modules in a modular codebase.

> **حالة المشروع:** نسخة تطويرية تشمل نماذج البيانات وواجهات API ولوحات عرض. بعض الشاشات تحتوي بيانات توضيحية، والتكاملات الخارجية تحتاج استكمالًا واختبارًا قبل الاستخدام الفعلي.

## ماذا يفعل المشروع؟

ينظم المشروع بيانات خدمة استلام أغراض العميل ونقلها إلى المستودع وتخزينها ثم إعادتها. يربط طلب التخزين بالعميل والمندوب والأغراض والمبالغ والحالة التشغيلية، ويوفر وحدات مساندة لإدارة المؤسسة من واجهة واحدة.

دورة الطلب التي يمثلها نموذج البيانات:

```text
طلب جديد ← تعيين مندوب ← الاستلام ← النقل ← التخزين ← الإرجاع ← إتمام الطلب
```

هذه الحالات ممثلة في قاعدة البيانات؛ أتمتة الانتقالات والتحقق من قواعد كل مرحلة تحتاج تطويرًا إضافيًا.

### ما يميز تصميمه؟

- واجهات عربية باتجاه RTL مع وضع فاتح وداكن ولوحات مخصصة بحسب نوع المستخدم.
- تقسيم وظيفي إلى تطبيقات Django مستقلة لتسهيل التطوير والصيانة.
- واجهات REST مع البحث والتصفية والترقيم في عدد من الوحدات، وتوثيق Swagger / OpenAPI.
- SQLite للتطوير المحلي وإعداد اختياري لـ PostgreSQL.
- بنية أولية للتحديثات اللحظية باستخدام Channels، وتهيئة Celery للمهام الخلفية.
- لوحة Django Admin لإدارة السجلات، وملفات Docker وNginx كأساس لإعداد بيئة تشغيل.

## التقنيات

Python · Django (`>=5.0,<5.2`) · Django REST Framework · SimpleJWT · HTML/CSS/JavaScript · Channels · Redis · Celery · PostgreSQL / SQLite · Docker · Nginx

ملف Docker يستخدم Python 3.12. راجع [requirements.txt](requirements.txt) للاعتماديات المعلنة؛ وجود مكتبة ضمن القائمة لا يعني اكتمال تكاملها.

## التشغيل المحلي

### 1. تنزيل المشروع وإعداد البيئة

```powershell
git clone https://github.com/Osama71627/Deposits.git
cd Deposits
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

على Linux/macOS استخدم `source .venv/bin/activate` و`cp .env.example .env` بدل أوامر التفعيل والنسخ الخاصة بـ PowerShell.

### 2. إعداد قاعدة البيانات وتشغيل الخادم

ضع قيمة عشوائية خاصة بك لـ `SECRET_KEY` في `.env`، ثم شغّل:

```shell
python manage.py migrate
python manage.py createsuperuser
python manage.py check
python manage.py runserver
```

المشروع يستخدم SQLite افتراضيًا. لعرض لوحة الإدارة المخصصة، عيّن `user_type` للحساب إلى `ADMIN` من لوحة Django Admin؛ صلاحية superuser مستقلة عن هذا الحقل.

| الصفحة | المسار المحلي |
|---|---|
| الرئيسية | http://127.0.0.1:8000/ |
| تسجيل الدخول | http://127.0.0.1:8000/login/ |
| لوحة المستخدم | http://127.0.0.1:8000/dashboard/ |
| إدارة Django | http://127.0.0.1:8000/admin/ |
| توثيق API | http://127.0.0.1:8000/api/docs/ |
| مخطط OpenAPI | http://127.0.0.1:8000/api/schema/ |

### إعداد الخدمات الاختيارية

- **PostgreSQL:** اضبط `USE_POSTGRESQL=True` ومتغيرات `DB_*` في `.env`.
- **WebSocket وCelery:** تحتاج Redis؛ عناوين Redis الحالية ثابتة على localhost في `config/settings.py` ويجب تعديلها بحسب بيئة التشغيل.
- **Docker:** الملفات ضمن `docker/` نقطة بداية. قبل تشغيلها، فعّل PostgreSQL صراحةً، واضبط عناوين Redis وأسرار البيئة. لم يتم التحقق من تشغيل الحاويات ضمن إعداد هذا المستودع.

## حدود النسخة الحالية وخطوات التطوير

- بعض النماذج والرسوم البيانية والخرائط في الواجهة توضيحية وتحتاج ربطًا كاملًا بواجهات API.
- بوابات الدفع وFirebase وGoogle Maps وZATCA تتضمن إعدادات أو نماذج تمهيدية؛ لا يمثل المشروع تكاملًا مكتملًا أو اعتمادًا للامتثال الضريبي.
- وجود حقول QR والمناطق الجغرافية لا يعني تنفيذ توليد الرموز أو التحقق الجغرافي تلقائيًا.
- توجد أدوار للمستخدمين، لكن يلزم استكمال صلاحيات الوصول على مستوى السجلات والقنوات اللحظية واختبار عزل بيانات العملاء.
- قبل الإنتاج، يجب ضبط `DEBUG` و`ALLOWED_HOSTS` وCORS والأسرار وHTTPS، وإكمال اختبارات العمليات والتكاملات.
- تطبيق Flutter، تحسين المسارات، والتقارير الآلية المتكاملة فرص للتطوير المستقبلي وليست مخرجات مكتملة في هذا المستودع.

لا تُرفع قاعدة البيانات المحلية أو ملفات المستخدمين أو البيئة الافتراضية أو `.env` إلى GitHub. تُحفظ migrations مع الكود لإتاحة إنشاء قاعدة البيانات من المصدر.

للتفاصيل راجع [التوثيق المعماري](docs/ARCHITECTURE.md).
